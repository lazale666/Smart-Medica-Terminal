# Qt 客户端构建说明

本文档覆盖 `Client_Qt` 下两个工程：

- 普通用户客户端：`Client`
- 医生客户端：`Client_Doctor`

## 1. 工程文件

### 普通用户客户端

- 目录：`Client_Qt/Client`
- 工程文件：`dontknow.pro`

### 医生客户端

- 目录：`Client_Qt/Client_Doctor`
- 工程文件：`medical.pro`

## 2. 构建环境

推荐环境：

- Qt 6.x
- MinGW 64-bit
- Windows 10 / 11

### 普通用户客户端所需 Qt 模块

- `Qt Widgets`
- `Qt Network`
- `Qt Multimedia`
- `Qt TextToSpeech`

### 医生客户端所需 Qt 模块

- `Qt Widgets`
- `Qt Network`
- `Qt Multimedia`

## 3. 使用 Qt Creator 构建

### 3.1 普通用户客户端

1. 打开 Qt Creator。
2. 选择 `Client_Qt/Client/dontknow.pro`。
3. 选择一个可用的 `Desktop Qt 6.x MinGW 64-bit` Kit。
4. 点击“配置项目”。
5. 执行构建。

### 3.2 医生客户端

1. 打开 Qt Creator。
2. 选择 `Client_Qt/Client_Doctor/medical.pro`。
3. 选择一个可用的 `Desktop Qt 6.x MinGW 64-bit` Kit。
4. 点击“配置项目”。
5. 执行构建。

## 4. 命令行构建

### 4.1 普通用户客户端

```powershell
cd .\Client_Qt\Client
qmake dontknow.pro
mingw32-make
```

### 4.2 医生客户端

```powershell
cd .\Client_Qt\Client_Doctor
qmake medical.pro
mingw32-make
```

如果你的 Qt 没有加入 `PATH`，请改用完整路径，例如：

```powershell
D:\Qt\6.11.1\mingw_64\bin\qmake.exe dontknow.pro
mingw32-make
```

## 5. 输出位置

输出位置取决于构建方式。

### 命令行原地构建

通常会在工程目录下生成：

- `debug/`
- `release/`

当前仓库中已经存在这类原地构建产物。

### Qt Creator 阴影构建

Qt Creator 常见输出目录：

```text
build/Desktop_Qt_6_x_x_MinGW_64_bit-Debug/
build/Desktop_Qt_6_x_x_MinGW_64_bit-Release/
```

## 6. 可执行文件名称

### 普通用户客户端

- 常见输出：`dontknow.exe`

### 医生客户端

- 常见输出：`medical.exe`

## 7. 运行前准备

### 7.1 服务端

客户端运行前，建议先启动服务端：

```powershell
cd .\Server_python
python server.py
```

默认连接配置：

- IP：`127.0.0.1`
- 端口：`9999`

### 7.2 图片资源

客户端会加载 `Client_Qt/photo/` 下的资源文件，例如：

- `background.png`
- `dontganmao.png`
- `us.png`

源码中的 `resourcepaths.h` 已经实现了多路径搜索，但发布时仍建议把资源目录一起带上。

### 7.3 语音依赖

普通用户端如果需要完整语音体验，还需要：

- 麦克风权限
- 百度语音识别配置有效
- Qt `TextToSpeech` 运行环境可用

## 8. 发布与打包

Windows 下建议使用 `windeployqt`：

### 普通用户客户端

```powershell
windeployqt path\to\dontknow.exe
```

### 医生客户端

```powershell
windeployqt path\to\medical.exe
```

打包时建议同时包含：

- 可执行文件
- Qt 运行时 DLL
- `photo/` 目录

如果你需要保留历史记录和账号文件，还要注意：

- 普通用户端会生成 `users.json`
- 医生端会生成 `doctors.json`
- 聊天历史会生成在应用目录下

## 9. 常见问题

### `qmake` 不存在

原因：

- Qt 未安装
- Qt `bin` 目录未加入 `PATH`

处理：

- 在 Qt Maintenance Tool 中确认安装
- 直接使用 `qmake.exe` 完整路径

### 链接时报 `TextToSpeech` 相关错误

原因：

- 普通用户端依赖 `QT += texttospeech`
- 当前 Qt 安装不完整

处理：

- 给当前 Qt Kit 安装 `Qt TextToSpeech`

### 找不到 `Qt Multimedia`

原因：

- Qt Multimedia 模块未安装

处理：

- 在 Qt 安装器里补装 Multimedia 组件

### 程序运行但图片不显示

原因：

- `photo/` 目录未和程序一起发布
- 当前工作目录与资源目录不匹配

处理：

- 确保 `Client_Qt/photo/` 被复制到发布包

### 运行时连接不上服务端

原因：

- 服务端未启动
- `127.0.0.1:9999` 不可用
- 防火墙阻止了端口

处理：

- 先确认 `Server_python/server.py` 正在运行
- 在设置页核对 IP 和端口

## 10. 建议的构建顺序

推荐顺序如下：

1. 先启动并验证服务端
2. 构建普通用户客户端
3. 构建医生客户端
4. 先跑普通用户端 AI 问诊
5. 再跑医生端联调医患会话

这样排查问题更直接，因为服务端和 AI 链路是两个 Qt 客户端的共同基础。
